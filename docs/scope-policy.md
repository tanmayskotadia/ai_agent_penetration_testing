# Versioned runtime scope enforcement — T13

Users provide scope and reviewed permission at assessment time. General-purpose development needs no organizer answers or preloaded targets. A live-request scope must reference the same authority as its execution policy. Recorded imports cannot produce execution authority. The hackathon context still requires organizer authorization; general context supports asset-owner authorization. A reference/hash records a human review, not cryptographic proof of legal ownership.

`POST /api/v1/assessments/{id}/policies` requires an owning human reviewer, current scope/revision, authorization source/document digest, validity window, exact target host/protocol/port/path, reviewed IP pins/networks, exclusions, profiles and bounded rate/concurrency. Reviewer identity is derived server-side. Policies are immutable and unique per scope version; change the scope to replace one. Scope exclusions are inherited and cannot be removed by policy input. Policy expiry cannot exceed a supplied scope expiry.

`POST .../policies/{policy}/check` revalidates policy and DNS, returning `execution_enabled: false`. It is a diagnostic only. `workers/aegistrace_workers/policy.py` reloads authoritative policy/current scope at dispatch, re-resolves addresses, pins the exact reviewed set and atomically reserves rate/concurrency. There is no scanner task or public direct-dispatch endpoint. A caller cannot submit a prompt-derived policy object as database authority. Later dispatch must consume approval and perform its final preflight within the same transaction.

URL validation rejects userinfo, fragments, query-bearing action URLs, wildcards, noncanonical numeric hosts, scoped/mapped IPv6, mixed/double encodings, encoded path separators, backslashes and dot segments. HTTP(S) defaults are canonical; TCP/UDP require explicit ports. Paths match at segment boundaries. DNS changes fail closed; clients connect to a returned pinned IP, retain the intended HTTP Host/TLS name, and verify the actual peer. All redirects require a new policy check, with at most three hops; no client may enable automatic redirects around this gate. This implementation returns pins, not an unrestricted HTTP/scanner client.

Metadata, loopback, link-local, multicast and unspecified addresses are denied even if entered as targets. Explicit private lab destinations must be pinned inside reviewed networks. `CONTROL_PLANE_NETWORKS` adds deployment-specific protected CIDRs; configure the actual database/control/admin ranges before deployment. Known control-service names are always denied. A free-form public/private network allowlist or prompt cannot replace exact target rules.

Policy rows serialize against scope changes. Shared SQL usage reservations prevent rate/concurrency bypass across dispatch workers; completion must release exactly one reservation. SQLite obtains its write lock before reading counters; PostgreSQL uses row locks. Missing policy, stale scope, expired policy, missing profile, rebinding, protected peer and limit exhaustion all deny dispatch. Network-level restrictions and approval/stop checks remain additional required layers, not implied by this policy result.

`tests/test_policy.py` uses explicitly synthetic permission metadata and reserved addresses; no target is contacted. It exercises ambiguous URLs/IPv6, rebinding, redirects, exclusions, expiry, protected CIDRs, profile restriction, a concurrent reservation race, stale scope, missing policy and recorded-import denial. Hosted CI repeats the reservation/API path on PostgreSQL and validates migration rollback/forward. R03/R04/R07/R12/R31/W01 are enforced at this deterministic boundary; R24's genuine lab demonstration remains M01/later integration work.

Manual intervention for T13 implementation: none. Actual operators supply genuine authority at runtime; no local participant setup or organizer question is required for this engineering acceptance.
