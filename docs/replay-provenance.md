# Recorded replay and provenance — T22

Human reviewers create a private manifest from an existing usable Nmap candidate normalization snapshot. It binds original capture time, tool version, source run/import/evidence IDs, original SHA-256, parser revision, reviewed mapping and historical decision references. The manifest is content hashed and HMAC authenticated with the application key, and database triggers reject update/delete. Key rotation requires preserving the manifest-verification key or a deliberate migration; failure is explicit. Host/database administrators remain trusted. No public sample capture or genuine evidence is fabricated or bundled.

The default provenance is `test-only`, displayed as **RECORDED / TEST ONLY**. Reviewer-declared captures require capture/rights/authorization references and remain explicitly authenticity-unverified. A declaration is not independent proof and cannot promote the tool registry. Manifest references must belong to the same assessment. Recorded decisions are historical IDs, explicitly **not current authority**; replay never reapproves an action or runs a tool. Public manifests/fixtures are not created; metadata/reference fields must not contain credentials.

`POST .../replays/{id}/ingest` validates the manifest, reads the retained private original, creates a fresh import snapshot and executes the same isolated candidate normalization path. It rechecks current scope/exclusions and mapping; changed parser/source requires a newly reviewed manifest. Source run and capture time stay original; replay time never masquerades as a live scan timestamp. Repeated requests with the same idempotency key return the original receipt. An expired original cannot start a new replay. No target, model, intelligence source, shell or live queue is contacted.

Candidate API responses carry RECORDED/TEST ONLY or RECORDED / reviewer-declared-capture; authenticity unverified labels and replay-manifest hash/ID, preserve uncertainty and create zero findings/approvals. The current UI lets a reviewer upload an existing Nmap XML, inspect the normalization snapshot, create the manifest and re-ingest it; it labels this path as recorded input and never calls a scanner. The captured snapshot and original stay distinct from current live state. A report renderer is still unavailable and must preserve those labels when implemented. XML import is supported only through the candidate Nmap parser; the seven integrations are still planned pending genuine verification.

The **recorded replay implementation is delivered**: immutable replay controls, the upload-to-normalization UI flow and the integrated no-network replay path work. The genuine permitted corpus/demo required by T05/T20 and the prototype gate is still unavailable. The end-to-end handcrafted test covers no target contact, provenance/timestamps/hashes, idempotency, canonical links and database immutability in SQLite and actual CI PostgreSQL. It does not establish genuine capture authenticity, scanner accuracy or hackathon lab compliance. No participant local setup or organizer questions are needed for continued development; valid captures can be supplied as runtime inputs later.
