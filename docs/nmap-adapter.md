# Candidate Nmap normalization — T20

The authenticated workspace includes a **Recorded Nmap XML** flow for analysts to feed an existing authorized artifact into an assessment. It creates a recorded scope revision, links run/evidence metadata, hashes and encrypts the original, then invokes `POST /api/v1/assessments/{id}/imports/{import_id}/normalize-nmap`. This is recorded import, not a scan. The UI requires the source-reported tool version/capture time and a source or authorization reference; the reference is recorded as supplied, not independently verified. The same API remains available for automation.

Normalization produces source-linked canonical assets, open-port services and observations. Original bytes, declared tool version, capture time, run/evidence IDs and SHA-256 remain linked. Each port retains an XML pointer. Open, closed, filtered, unfiltered, mixed and unknown states remain distinct in the snapshot; only explicitly open ports create services. Summary counts remain summary counts, not invented individual ports. Missing product/version remains absent. Service identification confidence is source text, not a calibrated probability. No port, banner, version or CPE creates a vulnerability, CVE, severity or confirmed finding.

The parser follows Nmap's documented [XML interface](https://nmap.org/book/output-formats-xml-output.html) and [DTD](https://nmap.org/book/nmap-dtd.html), without fetching a DTD or stylesheet. It accepts IPv4/IPv6 source addresses, bounds input/nodes/depth/strings/hosts/port records/result size, rejects entities, and runs in the existing short-lived, secret-free, network-denied parser child. Complete host records before truncated XML can be retained as `partial`; unsafe structures publish no host data. Tool error/missing successful finish stays partial. All extracted/mapped assets must satisfy current import scope and exclusions before any canonical record is written. Explicit alias mapping is a user declaration, not DNS/authenticity proof or live authority.

Normalization commits a snapshot and canonical links atomically. Repeated imports of the same evidence reuse canonical assets/services/source observations; original run identity and per-import snapshot remain separate. Active scripts, source XML `args` and stylesheet instructions are never executed. Source display strings are escaped and secret-pattern/configured-key masked. Raw original retention/access remains enforced by the evidence store. Candidate snapshot access is authenticated; no model sees it automatically.

T20's **recorded-input implementation is delivered**. A genuine permitted live run, verified binary/version/edition/license, exact approved-argument/run capture, real worker collector transport and genuine native fixture comparison are still missing. T14's deployed runner gate also remains open. The default capability registry remains **planned**, with no live scan enabled. These explicit gates are not replaced by handcrafted XML tests or an imported sample.

`tests/test_nmap.py` labels all native-format input as handcrafted test-only and covers states, IPv6, missing versions, error/truncation, entity rejection, source hash/IDs, repeated evidence, scope denial and actual PostgreSQL intake in CI. The frontend upload, scope/run/evidence creation, normalization and replay path uses the same API and is covered by frontend build and CI. No organizer questions or local participant setup are needed to use this boundary. Runtime users provide authorized targets and permitted evidence later.
