# Stop, cancellation and validation boundaries — T17

`POST /assessments/{id}/controls/stop` persists a stopped epoch, revokes pending/approved grants and cancels queued claims before start. It serializes with approval consumption and worker start. New requests/consumption/start fail while stopped. A reviewer/admin may explicitly resume only after running/unknown/reset-required work is reconciled; resume never restores old approvals. The human review UI exposes the stop action and displays separate queued, running-cancel and unknown counts.

`POST .../controls/jobs/{claim}/cancel` cancels an unstarted claim or requests cancellation of an active worker. `GET .../controls` shows worker/kind/deadline/lease/state and marks expired leases unknown. It never calls an unavailable remote tool API and then pretends cancellation succeeded. Internal worker start rechecks current policy, action integrity and human authority after locking; five-second leases fence reports/heartbeats to the registered worker ID/epoch. Late/foreign worker completions are rejected.

The shared trusted-worker supervisor runs an explicit argv vector with `shell=False`, no stdin and no inherited application/evidence/provider secrets. It checks stop/deadline every 50 ms, fails closed on control-channel errors, tracks descendants, uses process groups on Linux and terminates/kills/waits with bounds. It reports whether its owned processes are confirmed no longer executing. These are internal primitives, not a public arbitrary-command endpoint. Adapters must use reviewed command builders and isolated runtime policy before invoking them.

This supervisor is not a cgroup/container-kill service and cannot guarantee control of arbitrary escaped/detached descendants, a compromised kernel, or remote scanner jobs without a verified cancellation API. Scanner-specific termination, host cgroup teardown and real collector integration still need the actual runner/native-adapter work tracked with T14 and later milestones. On lost confirmation, preserve unknown state and conservative reservations; do not automatically redispatch a consumed approval.

Active-web or state-changing validation requires reset evidence after confirmed termination. Unreconciled/reset-required work blocks resume. `POST .../controls/jobs/{claim}/evidence` accepts an owning human reviewer's termination/reset attestation only with a hash-checked private original, same-assessment source reference and capture time after start. It records `termination-attested`/`reset-attested`, source and reviewer, not an automatic claim that a real target is clean. Genuine cleanup evidence must be inspected by the operator. Metasploit and arbitrary validation modules remain disabled by default; no payload, persistence, lateral movement or uncontrolled callback capability is provided.

All target state, original evidence, audit and report references remain separate. Cancellation does not delete them. Confirmed terminated non-state-changing jobs release limits; unknown work does not. Stateful work releases its reservation only after the evidence-backed human reset attestation. Queued cancellation is exact once and keeps the consumed approval consumed.

## Verification

`tests/test_control.py` covers stop-before-dispatch, no restoration on resume, queued cancellation, scanner/report-labelled control leases (synthetic jobs, not real report/scan engines), disconnected/unknown fencing, reset-required denial and evidence-bound reset attestation. It launches actual harmless Python parent/child processes and verifies tree termination, deadlines and secret-free environments. An integrated API → persisted stop → worker heartbeat → actual owned process termination → confirmed status test asserts bounded fixture latency. No security target is contacted; no actual scanner/report output is fabricated. Hosted CI repeats PostgreSQL stop/disconnection checks and the Linux process tests.

Sources: [Python subprocess](https://docs.python.org/3.12/library/subprocess.html), [psutil process recipes](https://psutil.io/recipes/). R04/R10/R12/R26/R31/R34 are enforced at the control boundary. Manual intervention now: none; actual operators supply genuine reset/termination evidence only when a real assessment needs it. No local installation or organizer questions are required for this engineering scope.
