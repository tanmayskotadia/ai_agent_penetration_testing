# Nikto recorded JSON import (T26)

The product accepts a user-supplied Nikto JSON export as recorded evidence. It does not install, invoke, or connect to Nikto and does not contact targets. Current source inspection targets the report array introduced by Nikto 2.6.0's rewritten JSON plugin; the parser is deliberately version-gated to concrete `2.6.patch` version strings. The upstream release notes state that 2.6.0 changed JSON/XML formats and 2.6.1 continued the report behavior, so older exports are quarantined instead of guessed. Nikto documents JSON as a supported file output format. The supplied version is metadata and does not authenticate the original program.

The normalizer captures each reported test ID, reference label, message, HTTP method, URL path and source JSON pointer as a source-linked observation, explicitly classified as a server configuration observation. It drops query strings from normalized URIs and does not copy request/response bodies. It maps a CVE or CWE into the shared correlation fields only when exactly one syntactically supported identifier of that type appears in a string reference; the original reference label and extracted reference list are retained. These are source-reported identifiers, not independently validated assignments. Multiple references of the same type remain visible but are not selected for correlation. It does not assign severity or confidence and does not create confirmed findings. All in-scope and exclusion checks happen before normalized rows are written; any out-of-scope reported URL quarantines the whole import. Empty reports are retained as zero-observation records and never establish coverage. Missing identifiers remain blank rather than being fabricated. Query values stay only in the encrypted original source evidence.

This remains a candidate import normalizer, not a verified product integration. Genuine version-matched captures, redaction review and authorized demonstration evidence are still required before any registry status can change. Never treat the user-entered version string as proof of the source program.

References: Nikto's [2.6.0 and 2.6.1 release notes](https://github.com/sullo/nikto/releases) describe the JSON/XML report changes; the [Export Formats guide](https://github.com/sullo/nikto/wiki/Export-Formats) lists JSON output; and the [current JSON reporter source](https://github.com/sullo/nikto/blob/main/program/plugins/nikto_report_json.plugin) shows the report array, host-level `vulnerabilities`, and their `id`, `references`, `method`, `url`, and `msg` fields. This source reference is format guidance, not an authenticity claim about an imported file.
